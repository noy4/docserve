docserve Plan

Implementation roadmap to build docserve.

Roadmap

Phase 1 — Server core P0
The HTTP layer: docsDir validation, URL mapping, MIME, status codes, and the state file.
  • Scaffold cli/: package.json (name, bin, type, files, engines), bin.mjs stub, server/index.mjs
  • docsDir resolution + validation (missing → exit 1)
  • URL mapping: /, /index.html → gallery template; raw static files; MIME map; 400 / 403 / 404
  • server/state.mjs: write state.json on bind, remove on SIGINT/SIGTERM, pid liveness + stale self-repair

Verify: node cli/bin.mjs ~/reports — curl /, raw page, traversal 403, bad escape 400

Phase 2 — /api/files + gallery P0
File metadata for /api/files and the gallery UI ported from docview.
  • server/files.mjs: recursive *.html listing (exclude index.html), <title> / created_at extraction (4 KB head → 1 MB fallback), git date maps (cached per repo root), sort by created desc
  • index.html: port the docview gallery — card grid, lazy iframes (rootMargin: 400px, max 3 concurrent), copy path

Verify: cards render with resolved dates; nested assets load

Phase 3 — Live reload P0
WebSocket broadcast, fs.watch detection, and page injection.
  • server/inject.mjs: reload client + copy button before the last </body>, < → \u003c escaping, iframe early-return
  • WS server /__reload: handshake, text frames, ping → pong (RFC 6455 subset)
  • UpdateListener: fs.watch(docsDir, { recursive: true }) filtered to *.html, 50 ms debounce batch, known-files tracking → contentSetChanged

Verify: edit reloads its own tab only; add/delete reloads the gallery; previews never reload

Phase 4 — CLI P1
Lifecycle commands: stop/status, background spawn, single-instance guard.
  • stop (SIGTERM + clear state; stale state removed silently) / status (exit 1 when none)
  • --background (detached spawn), --open, --port fallback +1 (≤ 20 tries)
  • Single-instance rule: same docsDir → open its URL; different → error prompting docserve stop
  • -h / -v

Verify: start → status → stop cycle; background + open; stale state.json

Phase 5 — Tests P1
Port the docview test suite to the new modules.
  • Port docview/serve.test.mjs → cli/server.test.mjs, run with node --test
  • Update pageId assertions: content:foo.html → foo.html
  • Drop the root:index.html gallery-edit case — the gallery is a package template now, not a watched file
  • Isolation: DOCSERVE_STATE env override for the state path + a random --port per run (parallel-safe)

Verify: node --test cli/ green

Phase 6 — Desktop app P2
macOS tray client controlling the CLI.
  • Electron zero-window main process; tray icon (outline when stopped / filled when running)
  • Start/stop toggle spawning the CLI; Open reads the URL from state.json
  • State watch: fs.watch + 2 s polling + pid liveness → menu rebuild (watch only ~/.cache/docserve/)
  • Change Folder… → stop → restart; remember the last folder in desktop.json
  • Quit → stop → app.quit(); first launch: symlink the CLI to ~/.local/bin/docserve

Verify: all menu flows, including a folder switch while running
