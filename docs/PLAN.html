IMPLEMENTATION PLAN

docserve Plan

Implementation roadmap to build docserve.

Roadmap

Phase 10 — Dev sandbox P2
Run a dev instance next to the installed app — separate user data and state.
Auto dev mode
an unpackaged app detects dev mode on its own and runs on separate user data and state, so two menu bar icons coexist
Sandboxed state
recent folders and the resume set stay inside the dev sandbox
Skip symlink in dev
dev never rewrites the CLI symlink owned by the installed app
Dev tray icon
a distinct menu bar icon to tell the dev instance apart
Phase 9 — Multiple folders P1
Serve several folders at once, one process and one port per folder.
Per-instance state
one state file per running folder under ~/.docserve/state/; dead entries are pruned automatically
Single-instance rule per folder
starting a running folder again just opens its URL; a different folder starts its own instance on the next free port
stop / status
docserve stop stops everything, docserve <dir> stop just that folder, status lists what's running
Tray: folder list
one row per running folder (open / stop), plus Add Folder…, Stop All, and the running set restored on the next launch
Tests
two folders on distinct ports, per-folder reload and stop, each test run isolated in its own temp home
Phase 8 — npm publish P2
Publish the CLI to npm as the scoped @noy4/docserve.
Package metadata
npm metadata filled in — links, public access, provenance — with the docserve command name unchanged
First manual publish
the first release published by hand, then verified with npx @noy4/docserve
Trusted publishing
tagging cli-v* on GitHub publishes to npm automatically, with no npm token stored
Phase 7 — Distribution P2
An unsigned macOS DMG published on GitHub Releases.
Packaging-ready CLI resolution
the app finds the bundled CLI in both dev and installed layouts, with the docserve PATH fallback kept
electron-builder config
an unsigned DMG for arm64 and x64, bundled with the CLI, menu-bar only
App icon
the default Electron icon replaced in Finder and the installer
GitHub Release
DMGs for both architectures attached to GitHub Releases, with an Open Anyway install guide in the README
Update notice
the tray checks the latest release and offers a menu item to open its page (no auto-update)
Phase 6 — Desktop app P2
macOS tray client controlling the CLI.
Electron zero-window main process
tray icon (outline when stopped / filled when running)
Start / Stop toggle
spawn the CLI · Open reads the URL from state.json
State watch
fs.watch + 2 s polling + pid liveness → menu rebuild (watch only ~/.docserve/)
Change Folder…
stop → restart · remember the last folder in desktop.json
Quit & first launch
stop → app.quit() · symlink the CLI to ~/.local/bin/docserve
Phase 5 — Tests P1
End-to-end tests for injection, the reload broadcast, and the CLI lifecycle.
Test suite
cli/server.test.mjs — injection · /__reload broadcast · status codes · CLI lifecycle, run with node --test
Isolation
DOCSERVE_STATE env override for the state path · random --port per run (parallel-safe)
Phase 4 — CLI P1
Lifecycle commands: stop/status, background spawn, single-instance guard.
stop / status
SIGTERM + clear state; stale state removed silently · status exits 1 when none
--background · --open · --port
detached spawn · open the browser · fallback +1 (≤ 20 tries)
Single-instance rule
same docsDir → point at its URL · different → error prompting docserve stop
-h / -v
show help / version
Phase 3 — Live reload P0
WebSocket broadcast, fs.watch detection, and page injection.
Page injection
server/inject.mjs — reload client + copy button before the last </body> · < → \u003c escaping · iframe early-return
WS server /__reload
server/websocket.mjs — handshake · text frames · ping → pong (RFC 6455 subset)
UpdateListener
server/watch.mjs — fs.watch(docsDir, { recursive: true }) filtered to *.html · 50 ms debounce batch · known-files tracking → contentSetChanged
Phase 2 — /api/files + gallery P0
File metadata for /api/files and the gallery UI.
File metadata
server/files.mjs — recursive *.html listing (exclude index.html) · <title> / created_at extraction (4 KB head → 1 MB fallback) · git date maps cached per repo root · sort by created desc
Gallery template
cli/index.html — card grid · lazy iframes (rootMargin: 400px, max 3 concurrent) · copy path
Phase 1 — Server core P0
The HTTP layer: docsDir validation, URL mapping, MIME, status codes, and the state file.
Scaffold cli/
package.json (name, bin, type, files, engines) · bin.mjs stub · server/index.mjs
docsDir resolution + validation
missing → exit 1
URL mapping
/, /index.html → gallery template · raw static files · MIME map · 400 / 403 / 404
Runtime state
server/state.mjs — write state.json on bind · remove on SIGINT/SIGTERM · pid liveness + stale self-repair
