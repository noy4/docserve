DOCSERVE PLAN · DOCKS AS PLUGINS

Dock plugin plan

No TypeScript. No React. No build. Just modules the browser can run.

Goal

The v4 plan already injects a dock into every served page. This plan makes the dock itself the extension point: a plugin adds a dock, not just a button.

Goal: a plugin can create its own dock container with its own position, order and items, using one published context object. Built-in features ship as plugins built on the same contract.
Non-goal: loading third-party plugins from disk or the network. The contract is fixed first; external loading is a later phase.

Injection contract

The inline client in inject.html is replaced by two static tags. Everything else moves into the widget.

StepBehavior
MarkA marker meta tag makes injection idempotent.
Insert<link rel="stylesheet" href="/__docserve/widget.css"> and <script type="module" src="/__docserve/widget.js" data-page="…"> before </body>.
FallbackNo </body>: append at the end. Non-HTML responses are untouched.
SkipIframe previews get no widget (server check plus a window.self !== window.top guard).
Serve/__docserve/widget/* reads files per request with no-store, so edits need no restart.
Relative imports: the widget entry must only import siblings by relative path. A bare specifier would fail in the browser because nothing rewrites it.

Plugin, dock and RPC contract

One context object, one dock API, one in-page RPC bus. A plugin that only uses these can later be moved to an external file without changes.

/** @typedef {Object} DocservePlugin
 *  @property {string} id
 *  @property {(ctx: DocserveContext) => void | (() => void)} setup */

ctx.page                                  // current page from data-page
ctx.rpc.register(name, fn)                // → unregister()
ctx.rpc.has(name) / ctx.rpc.call(name, ...args)
ctx.docks.create({ position, order })     // → DockHandle (new dock)
ctx.dock                                  // default dock, kept for compatibility
dock.add({ id, label, icon, order, group, href?, onClick?, isActive? })
ctx.ui.panel({ side, width, open, element })
ctx.ui.style('/__docserve/widget/plugins/x.css')
ctx.ui.announce(message)
ctx.pages.list({ force })                 // thin wrapper over RPC
ctx.pages.resolve(page)
ctx.on('change' | 'open' | 'start', fn)   // → off()
RuleReason
docserve: is reserved for core methods.Plugins use plugin:<id>:<method>; no silent shadowing.
Duplicate register throws.Composition errors surface at startup, not at call time.
call always returns a promise.Callers never branch on sync versus async.
setup may return a cleanup function.RPC, listeners, panels and dock items can all be removed.
ctx.rpc is not exposed on window.A served page must not be able to drive the dock.
Why RPC: plugins must not import each other. The bus is the only channel, which keeps the dependency graph flat and makes cleanup provable.
Why WebSocket stays: websocket.mjs already has the handshake and ping/pong with zero dependencies, and both the gallery and every dock can share /__reload. Moving to SSE would rewrite working code for no gain.

Steps

StepWorkDone when
1 ✓ Move server/ → src/node/, test → test/, files and typecheck scripts, tsconfig.json, dev script. Same behavior; npm test green; CLI start / status / stop unchanged.
2 Widget widget/ skeleton (host, api, rpc, docks, dock-item, pages, live) plus home. Replace inject.html with two tags and add the /__docserve/widget/* route. One home button bottom-right on any page; absent in previews; no duplicates after reload.
3 RPC Register docserve:pages:list and docserve:pages:resolve; route ctx.pages through them; port copy. Copy writes the absolute path; unknown method rejects.
4 Sidebar Panel plus storage: open state, [ toggle, Esc, current page marker, refetch on change. State survives reload; current page highlighted; list matches the gallery.
5 Docks ctx.docks.create() with position, order and stacking; one shared fixed layer; safe-area insets. A second dock renders beside the default one without overlap.
6 Harden shared/types.d.ts plus JSDoc, cleanup on every plugin, remove dead inline CSS, tsc --checkJs green. Typecheck has zero errors and no page shows leftover inline styles.
Acceptance: a new dock can be added by writing one file that calls ctx.docks.create(); built-in sidebar, home and copy use that same path; every plugin can be removed without leaving DOM, listeners or storage behind.

Known pitfalls

npm filessrc/ must be listed or the package ships nothing
CIpublish-cli runs npm test; keep it green or adjust
DesktopextraResources copies cli/ wholesale, so no build step
Reconnectdock retries with backoff; never reload the page on close
Socket closehandle 0x8 frames so dead clients leave the set
Typechecktypescript stays a devDependency; runtime stays bare
Rejected: adding a bundler for the widget, migrating to React, or introducing chokidar / h3. Each one breaks the "clone and run" property the CLI still has.
